    Do zero ao primeiro teste

    Instale, teste e deixe o Reels Engine IA pronto para trabalhar com o Claude. Não precisa saber programar: cada comando vem pronto para copiar, e cada termo técnico é explicado na primeira vez em que aparece.

    1. Node 245 min
    2. Baixar o projeto3 min
    3. Terminal e testes5 min
    4. Cowork ou Claude Codeescolha
    5. Agente de Rendersó Windows · 2 min
    6. Studio2 min
    7. Conferir1 min

    Depois de instalar, siga para o Manual de Uso: ele mostra como pedir um vídeo, do briefing ao MP4.

    1

    Antes de começar

    {{I:clock}} 2 minutos de leitura

    O Reels Engine IA é um conjunto de pastas e arquivos que fica no seu computador. O Claude lê as regras que estão nele, monta o vídeo em código e gera um arquivo MP4 pronto para o Instagram, sempre com a sua aprovação nas etapas importantes.

    O que você precisa

    ItemDetalhe
    ComputadorWindows 10 ou 11, macOS ou Linux. O Agente de Render (render sem terminal) é só para Windows.
    Espaço livreCerca de 1 GB para o motor e as peças dele, mais o espaço dos seus vídeos.
    InternetNa instalação, nas atualizações e no primeiro render (o Remotion baixa um navegador interno de uns 100 MB).
    ClaudeO app Claude para computador com o Cowork, ou o Claude Code. A diferença está em Cowork ou Claude Code?
    TempoUns 20 minutos, do zero ao primeiro teste.

    Onde guardar a pasta

    Escolha agora o lugar definitivo. Mudar depois é possível, mas dá trabalho (veja Mudar a pasta de lugar).

    {{I:check}} Bom

    Caminho curto, fora de pastas sincronizadas
    • C:\Projetos\reels-engine-ia
    • /Users/voce/Projetos/reels-engine-ia
    • Nomes sem acento e sem espaço

    {{I:x}} Evite

    Pastas que a nuvem sincroniza
    • C:\Users\voce\OneDrive\…
    • Área de Trabalho e Documentos, quando o OneDrive, o iCloud ou o Dropbox cuidam delas
    • C:\Users\voce\Vídeos\Reels Engine (cópia)\
    {{I:warn}}
    Por que fora do OneDrive?

    O motor guarda milhares de arquivos pequenos (a pasta node_modules) e gera vídeos grandes. A sincronização deixa tudo lento e pode travar arquivos no meio de um render. No Windows 11, a Área de Trabalho e os Documentos costumam estar no OneDrive: se o caminho tiver OneDrive, ou se o Explorador mostrar uma nuvem na coluna “Status”, escolha outro lugar.

    2

    Instalar o Node 24

    {{I:clock}} 5 minutos{{I:check}} Resultado: node -v mostra v24

    Node.js (ou só “Node”) é o programa que roda o motor no seu computador. Ele é gratuito, e o motor foi testado na versão 24. Instale uma vez; ele não abre janela nenhuma depois.

    1. Abra a página da versão 24

      nodejs.org/dist/latest-v24.x/ {{I:out}}

      É uma lista simples de arquivos. Baixe o que termina em -x64.msi (por exemplo, node-v24.x.x-x64.msi). Se o seu notebook tem processador Snapdragon (ARM), baixe o que termina em -arm64.msi.

    2. Dê dois cliques no arquivo baixado

      Vá clicando em Next e aceite a licença. Os caminhos sugeridos podem ficar como estão.

    3. Na tela “Tools for Native Modules”, deixe a caixa desmarcada

      Essa opção instala Python, Visual Studio e outras ferramentas que o motor não usa: são vários gigabytes e muito tempo de instalação.

    4. Clique em Install e depois em Finish

      Se o Windows pedir permissão, confirme.

    1. Abra a página da versão 24

      nodejs.org/dist/latest-v24.x/ {{I:out}}

      Baixe o arquivo que termina em .pkg (por exemplo, node-v24.x.x.pkg). Ele serve para Mac com chip Apple e com Intel.

    2. Dê dois cliques no arquivo e siga o instalador

      Continuar, aceitar a licença, Instalar. O Mac pede a senha do seu usuário.

    1. Abra a página oficial de download

      nodejs.org/en/download {{I:out}} → escolha a versão 24, o sistema Linux e o método nvm. A página mostra os comandos exatos.

    2. Rode os comandos da página no terminal

      O último deles instala a versão 24:

      Terminal
      nvm install 24
    {{I:info}}
    A página oficial sugere outra versão?

    O site do Node destaca sempre a versão mais nova. Versões mais novas também funcionam, mas a 24 é a testada: prefira o link direto acima.

    Confira a instalação

    Abra um terminal novo (os que já estavam abertos não enxergam o Node recém-instalado). Pode ser em qualquer pasta: no Windows, aperte Win, digite cmd e aperte Enter. Depois rode:

    Terminal · qualquer pasta
    node -v
    {{I:check}}Certo
    v24.13.0

    Começa com v24. Os números depois podem ser outros.

    {{I:x}}Errado
    v20.11.1
ou
'node' não é reconhecido como um comando…

    Veja Node errado ou Node não encontrado.

    Para quem já programa

    O repositório tem .nvmrc com 24 e engines pedindo >=24; nvm, fnm e Volta funcionam normalmente.

    Baixar o projeto

    {{I:clock}} 3 minutos{{I:check}} Resultado: uma pasta reels-engine-ia com package.json dentro

    1. Baixe o ZIP

      Pelo link direto reels-engine-ia-main.zip, ou na página github.com/BRIANICK-dev/reels-engine-ia {{I:out}} → botão verde Code → Download ZIP.

    2. Windows: desbloqueie o ZIP antes de extrair

      Botão direito no ZIP → Propriedades → no pé da aba Geral, em Segurança (“Este arquivo veio de outro computador…”), marque Desbloquear → OK. Assim o Windows não reclama depois, ao instalar o Agente de Render. Se a opção não aparecer, siga em frente.

    3. Extraia direto no lugar definitivo

      Botão direito → Extrair tudo…. No campo de destino, escolha a pasta que você definiu em Onde guardar (por exemplo, C:\Projetos) e apague o final \reels-engine-ia-main que o Windows sugere. Isso evita a “pasta dentro da pasta”. No Mac, basta dar dois cliques no ZIP.

    4. Renomeie a pasta

      De reels-engine-ia-main para reels-engine-ia. Não é obrigatório, mas deixa os caminhos mais curtos e combina com este manual. Se você baixou o ZIP de uma versão, na página Releases, a pasta vem com o número dela (por exemplo, reels-engine-ia-1.0.0): renomeie do mesmo jeito.

    Certo
    • {{I:folder}}C:\Projetos
      • {{I:folder}}reels-engine-ia
        • {{I:folder}}docs
        • {{I:folder}}projects
        • {{I:file}}package.jsonaqui é a raiz
    Pasta dentro da pasta
    • {{I:folder}}C:\Projetos
      • {{I:folder}}reels-engine-ia-mainsó tem outra pasta dentro
        • {{I:folder}}reels-engine-ia-main
          • {{I:file}}package.json

    Nas versões mais novas do Windows 11 a pasta dupla nem chega a aparecer; a conferência é a mesma: a pasta certa é a que tem package.json. Já extraiu com a pasta dupla? Recorte a pasta de dentro, cole em C:\Projetos e apague a de fora, que ficou vazia.

    Com o git {{I:out}} instalado, abra o terminal na pasta onde o projeto vai morar (por exemplo, C:\Projetos) e rode:

    Terminal · na pasta escolhida
    git clone https://github.com/BRIANICK-dev/reels-engine-ia.git
cd reels-engine-ia

    git é a ferramenta que baixa e atualiza projetos guardados no GitHub. clone é a cópia completa, que depois se atualiza com um comando (veja Atualizar o motor).

    Abrir o terminal e testar

    {{I:clock}} 5 minutos{{I:check}} Resultado: “fail 0”

    Agora você vai dar os dois primeiros comandos: um que instala as peças de que o motor precisa e outro que confere se está tudo certo. Os dois são digitados no terminal.

    Terminal é uma janela onde você escreve ordens para o computador em vez de clicar. No Windows ele se chama Prompt de Comando. Cada ordem é um comando: você digita (ou cola) e aperta Enter.

    Abra o terminal na raiz do projeto

    O terminal sempre “está” dentro de alguma pasta, e os comandos do motor só funcionam na raiz.

    Raiz é a pasta principal do projeto: a que tem dentro package.json, CLAUDE.md e INSTALAR-AGENTE-DE-RENDER.cmd. Se você vê só outra pasta com o mesmo nome lá dentro, entre nela: a raiz é a de dentro.

    1Abra a pasta do projeto no Explorador e confira se package.json está nela.

    2Clique num espaço vazio da barra de endereço. O caminho fica selecionado.

    3Digite cmd por cima do caminho e aperte Enter.

    4Abre o terminal já dentro da pasta. Deixe essa janela aberta.

    {{I:warn}}
    Abriu “PowerShell” em vez de “Prompt de Comando”?

    Feche e repita digitando exatamente cmd. No PowerShell, o npm pode ser bloqueado por uma regra de segurança do Windows (“a execução de scripts foi desabilitada”).

    1. Abra o app Terminal

      Aperte ⌘ + Espaço, digite Terminal e aperte Enter.

    2. Digite cd e um espaço

      Não aperte Enter ainda. cd quer dizer “entre na pasta”.

    3. Arraste a pasta do projeto para dentro da janela

      Do Finder para o Terminal. O caminho da pasta é escrito sozinho. Agora aperte Enter.

      Terminal
      voce@mac ~ % cd /Users/voce/Projetos/reels-engine-ia
voce@mac reels-engine-ia %

      O nome da pasta antes do % mostra que você está na raiz.

    1. Abra a pasta do projeto no gerenciador de arquivos

      Confira se package.json está nela.

    2. Clique com o botão direito num espaço vazio → “Abrir no terminal”

      O nome pode variar conforme a distribuição. Alternativa: abra o terminal, digite cd, um espaço, arraste a pasta e aperte Enter.

    Instale as peças do motor

    Copie o comando abaixo, cole no terminal (Ctrl + V ou botão direito do mouse; no Mac, ⌘ + V) e aperte Enter.

    Terminal · na raiz
    npm ci

    npm é o instalador que vem junto com o Node. npm ci baixa as dependências — os programas prontos que o motor usa, como o Remotion — nas versões exatas que foram testadas. Tudo vai para a pasta node_modules, dentro do projeto.

    Demora de 1 a 3 minutos e só precisa ser feito uma vez (e de novo depois de cada atualização do motor). No fim, aparece algo assim:

    O que esperar
    npm warn deprecated …          ← avisos assim são normais
added 254 packages, and audited 255 packages in 52s
49 packages are looking for funding
found 0 vulnerabilities

    Os números podem ser diferentes. O que importa é não aparecer npm error no final. Apareceu? Veja npm ci falhou.

    Confira se está tudo certo

    Terminal · na raiz
    npm test

    O motor testa a si mesmo: são dezenas de verificações automáticas, que levam cerca de 1 minuto. Muita coisa passa pela tela; só o resumo do final importa.

    {{I:check}}Tudo certo
    ✔ … (dezenas de linhas)
ℹ tests 104
ℹ suites 0
ℹ pass 104
ℹ fail 0
ℹ cancelled 0
ℹ duration_ms 41897

    tests e pass iguais, fail 0. Pode seguir. O total muda de uma versão para outra.

    {{I:x}}Algo falhou
    ✖ nome do teste que falhou
  AssertionError: …
ℹ tests 104
ℹ suites 0
ℹ pass 103
ℹ fail 1
ℹ duration_ms 40112

    fail maior que 0. Copie desde a primeira linha com ✖ até o fim e mande para o Claude no chat, ou veja Um teste falhou.

    {{I:check}}
    Pronto: o motor está instalado e testado.

    Pode fechar o terminal. No próximo passo você escolhe como vai trabalhar com o Claude.

    {{I:code}}
    Para quem já programa

    npm ci instala exatamente o que está no package-lock.json e nunca o altera; prefira-o a npm install. O npm sobe até a raiz se você rodar de uma subpasta, mas os scripts e este manual assumem a raiz. Para checar tipos: npm run typecheck.

    5

    Cowork ou Claude Code?

    {{I:clock}} 3 minutos{{I:check}} Resultado: você sabe quem vai gerar o MP4 final

    O motor funciona com as duas formas de usar o Claude no computador. A diferença principal é quem roda os comandos — e, por isso, quem gera o MP4 final.

    Render é a etapa em que o vídeo, que até então é código, vira um arquivo MP4 de verdade, pronto para postar. Leva de um a alguns minutos, conforme a duração e o computador.

    {{I:chat}} Cowork

    No app Claude para computador, sem terminal
    • Você conecta a pasta reels-engine-ia no app e conversa normalmente.
    • O Claude trabalha numa área própria na nuvem e grava os arquivos na sua pasta.
    • Para assistir ao vídeo, você abre o Studio com um comando que o Claude indica.
    • Render final: no Windows, o Agente de Render faz sozinho; no Mac e no Linux, você roda um comando quando o Claude pedir.

    {{I:term}} Claude Code

    O Claude dentro do terminal, no seu computador
    • Você abre o terminal na raiz e digita claude.
    • O Claude roda os comandos direto no seu computador: cria o projeto, abre o Studio, renderiza.
    • Não precisa do Agente de Render, em nenhum sistema.
    • Combina com quem já está à vontade no terminal.

    Quem gera o MP4 final

    CoworkClaude Code
    WindowsO Agente de Render, sozinho, depois da sua autorizaçãoO Claude, no terminal
    macOSVocê: npm run render -- <slug>O Claude, no terminal
    LinuxVocê: npm run render -- <slug>O Claude, no terminal

    O <slug> é o nome curto do projeto (por exemplo, loja-exemplo-promo-natal). O Manual de Uso explica.

    {{I:info}}
    Por que o MP4 final não vem da nuvem?

    Um Reels final costuma ter de 40 a 100 MB, acima do limite de transferência da nuvem para o seu computador. Por isso o MP4 definitivo sempre nasce no seu computador. Prévias e imagens de conferência o Claude pode mandar pelo chat.

    Começar no Cowork

    1. Abra o app Claude para computador e entre no Cowork

    2. Conecte a pasta reels-engine-ia

      Escolha a raiz, a pasta que tem o package.json. É a única pasta que o Claude precisa enxergar.

    3. No Windows, instale o Agente de Render

      Uma vez só. Está na próxima seção.

    4. Mande a primeira mensagem

      Mensagem para o Claude
      Leia o CLAUDE.md da raiz e siga as regras dele. Depois me diga a situação dos projetos.
    {{I:info}}
    Uma pasta “Claude outputs” apareceu?

    É onde o app guarda os arquivos que o Claude manda no chat (prévias, imagens de conferência). Não faz parte do motor nem dos seus projetos: pode apagar quando quiser.

    Começar no Claude Code

    1. Instale o Claude Code

      Siga a documentação oficial {{I:out}}.

    2. Abra o terminal na raiz e digite claude

      Como em Abrir o terminal na raiz.

      Terminal · na raiz
      claude

    3. Mande a mesma primeira mensagem

      “Leia o CLAUDE.md da raiz e siga as regras dele. Depois me diga a situação dos projetos.”

    6

    Agente de Render Windows

    {{I:clock}} 2 minutos{{I:check}} Resultado: “Agente ativo agora: sim”

    Agente de Render é um programa pequeno que fica ligado em segundo plano no seu Windows, sem janela. Quando você autoriza o render no chat do Cowork, o Claude deixa um pedido numa pasta e o agente gera o MP4 no seu computador.

    {{I:info}}
    Precisa dele?

    Só se você usa o Cowork no Windows. Com o Claude Code, ou no Mac e no Linux, pule para o Studio.

    Instale (uma vez só)

    1. Na raiz, dê dois cliques em INSTALAR-AGENTE-DE-RENDER.cmd

      Abre uma janela preta, que mostra o andamento.

    2. Apareceu “Abrir Arquivo - Aviso de Segurança”?

      A janela diz “O fornecedor não pôde ser verificado. Tem certeza de que deseja executar este software?”. Clique em Executar. O aviso aparece porque o arquivo veio de um ZIP baixado da internet; você o evita desbloqueando o ZIP antes de extrair.

      Em alguns computadores o aviso é outro, “O Windows protegeu o computador”: clique em Mais informações → Executar assim mesmo. Prefere não passar por nenhum aviso? Use a aba Pelo terminal.

    3. Espere a mensagem final e aperte qualquer tecla

    Terminal · na raiz
    npm run agent:install
    {{I:check}}O que esperar no final
    ✔ Início automático criado:
  C:\Users\voce\AppData\…\Inicializar\ReelsEngineIA-AgenteRender-….vbs

✔ Agente de Render ATIVO (pid 1234).
  Ele liga sozinho a cada login no Windows e trabalha em segundo plano.

    Confira

    Terminal · na raiz
    npm run agent:status
    {{I:check}}Certo
    Agente de Render — início automático: INSTALADO
Agente ativo agora: sim (pid 1234, último sinal 2026-…)

    Aparece “não (sem sinal…)”? Veja Agente sem sinal. Para um diagnóstico completo (projetos, etapas, pedidos pendentes), rode npm run agent:check: ele só lê, não muda nada.

    No dia a dia

    • Ele liga sozinho quando você entra no Windows. Não precisa abrir nada.
    • Só renderiza depois que você autoriza o render no chat (o GATE 4).
    • Nunca sobrescreve um vídeo: cada render vira uma versão nova (v01, v02…), em projects/<slug>/renders/.
    • Um pedido nunca roda duas vezes, e um erro nunca se repete sozinho.

    Mudar a pasta de lugar ou remover

    O agente guarda o caminho da pasta. Para mudar a pasta de lugar: antes de mover, rode o comando abaixo; depois de mover, instale de novo. Para desinstalar, só o comando abaixo basta.

    Terminal · na raiz
    npm run agent:install -- --remover

    Remover o agente não toca nos seus projetos nem nos vídeos já gerados.

    Primeiro teste no Studio

    {{I:clock}} 2 minutos{{I:check}} Resultado: o vídeo de exemplo tocando no navegador

    Studio (Remotion Studio) é a tela de pré-visualização que abre no seu navegador. Ela mostra o vídeo de verdade, quadro a quadro, antes de virar MP4. É nela que você aprova cada vídeo.

    O motor vem com um projeto de exemplo, exemplo-loja-promo: o mesmo texto em três estilos visuais diferentes. Abra-o assim:

    Terminal · na raiz
    npm run studio -- exemplo-loja-promo
    O que esperar
    ▶ Studio: exemplo-loja-promo
  assets: projects/exemplo-loja-promo/assets/

Server ready - Local: http://localhost:3000
Built in 3891ms

    O navegador abre sozinho. Se não abrir, digite o endereço http://localhost:3000 no navegador. Deixe o terminal aberto enquanto usa o Studio.

    Composição é cada vídeo dentro de um projeto. No exemplo, Main é o vídeo principal e as Vitrine-… mostram o mesmo texto em outros estilos.

    Para fechar

    Volte ao terminal e aperte Ctrl + C. No Windows, se ele perguntar “Deseja finalizar o arquivo em lotes (S/N)?”, digite S e aperte Enter. Fechar a janela do terminal também funciona.

    {{I:info}}
    O Studio não gera o MP4

    Ele só mostra o vídeo. O arquivo final vem do render, depois da sua autorização: o Manual de Uso mostra o caminho completo.

    Atualizar o motor

    {{I:clock}} 5 minutos{{I:check}} Resultado: versão nova, seus projetos intactos

    Quando sair uma versão nova, leia o CHANGELOG.md dela para saber o que mudou. A sua versão atual está no arquivo VERSION, na raiz, e no topo deste manual.

    A atualização substitui
    • {{I:folder}}docs, engine, scripts, manuais
    • {{I:folder}}local.exemplo
    • {{I:folder}}projects/_MOLDE
    • {{I:folder}}projects/exemplo-loja-promo
    • {{I:file}}CLAUDE.md, package.json…
    Nunca é tocado
    • {{I:folder}}projects/<seus projetos>
    • {{I:folder}}clients/<suas fichas>
    • {{I:folder}}localsuas regras
    • {{I:folder}}.reels-enginefila do agente
    {{I:warn}}
    Personalizações vão em local/

    O que você mudar dentro de projects/_MOLDE, docs ou CLAUDE.md é substituído na atualização. Suas regras e preferências ficam em local/ (veja Camada local), que nenhuma atualização toca.

    1. Feche o Studio e os terminais abertos

    2. Baixe o ZIP novo e extraia numa pasta temporária

      Por exemplo, C:\Projetos\reels-engine-ia-nova (desbloqueie o ZIP antes, como em Baixar o projeto).

    3. Copie tudo da pasta nova para a sua

      Selecione todo o conteúdo da pasta nova (Ctrl + A), copie e cole dentro da sua pasta reels-engine-ia. Quando o Windows perguntar, escolha Substituir os arquivos no destino. Seus projetos, fichas e a pasta local não estão no ZIP, então continuam como estavam.

    4. Apague a pasta temporária

    5. Reinstale as peças e teste

      No terminal, na raiz: npm ci e depois npm test (o resultado precisa ter fail 0).

    6. Windows com o agente: reinicie o computador

      O agente volta já com a versão nova.

    Se o CHANGELOG.md da versão nova disser que algum arquivo foi removido, apague-o da sua pasta também.

    Terminal · na raiz
    git pull
npm ci
npm test

    No Windows com o agente, reinicie o computador depois (ou rode npm run agent:install de novo).

    Projetos já criados guardam uma cópia congelada do engine em src/engine/ e a versão em project.json → engineVersion: atualizar o motor não muda vídeos em andamento.

    Deu erro?

    Clique no problema para ver a solução

    Cada item mostra o sintoma (a mensagem que aparece), a causa e o que fazer. Se nada aqui resolver, copie as últimas linhas do terminal e mande para o Claude no chat: ele sabe ler esses erros.

    {{I:chat}}
    Travou num passo, ou instalou no macOS ou no Linux?

    Conte como foi no formulário “Relato de instalação” {{I:out}}: sistema, versão do Node, resultado do npm test, o passo em que travou e o que apareceu na tela. Relatos de instalação que deu certo também ajudam, principalmente de macOS e Linux. É preciso ter uma conta (gratuita) no GitHub.

    Node na versão erradanpm warn EBADENGINE Unsupported engine · node -v mostra v20 ou v22
    Causa

    Há uma versão mais antiga do Node instalada, e o motor precisa da 24 ou mais nova.

    Solução
    1. Instale a versão 24 como em Instalar o Node 24 (ela substitui a antiga).
    2. Feche todos os terminais e abra um novo.
    3. Confira com node -v e rode npm ci de novo.
